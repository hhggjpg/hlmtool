# 红楼梦人物关系分析工具

用大模型 API 自动读取《红楼梦》全 120 回正文，抽取人物和人物之间的关系，
生成人物表、关系表与关系图谱。

**当前状态**：✅ **已跑通全 120 回**（程高本，约 73 万字）。
共抽出 497 个人物、2022 条关系，原文依据忠实度 **99.3%**，实际花费约 ¥27。

> 开发过程、成本与经验总结见 docs/一页说明.md
> 数据质量记录与踩坑记录见 docs/数据问题清单.md
---

## 一、这个工具能做什么

读入章回体小说的正文，自动产出：

1. **人物表**：出现了哪些人物、各自出场多少次、集中在哪些回目
2. **关系表**：任意两个人之间是什么关系（亲属／主仆／社会／冲突／情感），并附原文依据
3. **关系图谱**：全书人物关系总图，以及任意单个人物的关系网络
4. **关系演变**：同一对人物在不同回目中的关系变化

## 三、快速开始

### 第 1 步：取得代码

**方式一：下载 ZIP**

打开仓库页面，点绿色的 `Code` 按钮 → `Download ZIP`，
解压后进入解压出来的文件夹。

**方式二：git clone**

```bash
git clone [你的仓库地址]
cd hlmtool
```

> 本项目目录名是 `hlmtool`（**中间没有空格**），
> 如果你解压后得到的文件夹名不同，请重命名成 `hlmtool`，
> 否则后面几步的命令要相应修改。

### 第 2 步：创建虚拟环境

**Windows（PowerShell）**：
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

> 如果报错"因为在此系统上禁止运行脚本"，先执行这一条再重试：
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```

**macOS / Linux**：
```bash
python3 -m venv .venv
source .venv/bin/activate
```

激活成功的标志：命令行最前面出现 `(.venv)`。

### 第 3 步：安装依赖

```bash
python -m pip install -r requirements.txt
```

**网络慢的话**，换国内镜像：
```bash
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 第 4 步：配置 API Key

复制 `.env.example` 为 `.env`：

```bash
copy .env.example .env        # Windows
cp .env.example .env          # macOS / Linux
```

然后打开 `.env`，把 `your_api_key_here` 换成你自己的 Key：

```
DEEPSEEK_API_KEY=sk-你的真实密钥
```

**注意**：
- 等号两边**不要有空格**，行尾也不要
- `.env` 已被 `.gitignore` 排除，**不会被上传**，可以放心填
- 绝对不要把 Key 直接写进任何 `.py` 文件

### 第 5 步：取得《红楼梦》全文（不花钱）

```bash
python scripts/fetch_text.py
```

会从公开仓库把程高本 120 回抓下来，存成 `data/raw/001.txt` ~ `120.txt`，约 2.5 MB。

- **已存在的文件会自动跳过**（所以中断后重跑不会浪费）
- 只想抓某一回：`python scripts/fetch_text.py 001`
- **仓库里已包含抓好的全文**，所以这一步通常会看到 120 行"已存在，跳过"

然后把它复制进 `data/clean/`（本项目不做额外清洗，只做"复制 + 逐字核对"）：

```bash
python scripts/make_clean.py
```

### 第 6 步：运行抽取（这一步会花钱，全本约 ¥27）

```bash
python scripts/extract_all.py
```

**必须在项目根目录运行**（脚本用的是相对路径）。

全 120 回预计 **2～4 小时**（每回一次请求，每次 1～2 分钟）。

> **注意**：仓库里已经包含了跑好的 `output/chapter_001.json` ~ `chapter_120.json`。
> 脚本会自动跳过已存在的文件（**避免重复花钱**），
> 所以你会先看到 120 行"已存在，跳过"。
>
> **想完整重跑一遍**，先删掉旧结果：
> ```bash
> del output\chapter_*.json        # Windows
> rm output/chapter_*.json         # macOS / Linux
> ```
>
> **想保留旧结果、同时跑新的**：把 `scripts/extract_all.py` 里的
> `OUT_SUFFIX = ""` 改成 `OUT_SUFFIX = "_new"`，新结果会存成
> `chapter_001_new.json`，不会覆盖原文件。

### 第 7 步：生成表和图（不花钱）

依次运行：

```bash
python scripts/verify_all.py      # 核对引用，输出准确率
python scripts/make_tables.py     # 生成人物表.csv 和 关系表.csv
python scripts/classify.py        # 关系归类，生成 关系表_分类.csv
python scripts/draw_graph.py      # 生成关系图 PNG
python scripts/changes.py         # 生成 关系演变清单.txt
```

全部产出在 `output/` 目录下。

## 四、脚本说明

| 脚本 | 作用 | 需要 API | 说明 |
|---|---|---|---|
| `fetch_text.py` | 下载全文 → `data/raw/` | 否 | 从公开仓库抓程高本 120 回 |
| `make_clean.py` | 原始文本 → 清洗后文本 | 否 | 本项目不做额外清洗，只做"复制 + 逐字核对" |
| `extract_all.py` | 正文 → 人物关系 JSON | **是** | **全项目唯一调用大模型的地方**，逐回处理 |
| `verify_all.py` | 核对"原文依据"是否忠实 | 否 | 把模型给的引文拿回原文逐句比对 |
| `make_tables.py` | JSON → 人物表 / 关系表 | 否 | 含别名合并（200+ 条）、去重、出场次数统计 |
| `classify.py` | 关系类型收敛为 5 类 | 否 | 用**关键词归类**（不是逐字匹配），能覆盖上百种自由标签 |
| `draw_graph.py` | 关系表 → 关系图 | 否 | 输出全图 + 单个主角的关系网；`TOP_N` 控制画多少人 |
| `changes.py` | 找出关系变化线索 | 否 | 回答"关系随情节怎么变化"，输出 `关系演变清单.txt` |
| `fix_085.py` | 修补第 85 回 | **是** | 整回会让模型"复读失控"，此脚本切两段抽再合并（见 docs/数据问题清单.md） |
| `check_names.py` | 人名点名（质检） | 否 | 确认核心人物名字完好无损 |
| `check_outputs.py` | 结构体检（质检） | 否 | 检查 JSON 格式、字段完整性 |
| `scan_pua.py` | 坏字符扫描（质检） | 否 | 找出源文本里的私有区字符 |

**提示词**放在 `prompts/` 目录里，脚本从文件读取，不写在代码里。
版本记录见 `prompts/README.md`。

## 六、数据来源

- **正文**：《红楼梦》程高本（一百二十回），公有领域
  - 取自公开仓库 [gitbook-hongloumeng](https://github.com/AnLittleHong/gitbook-hongloumeng) 的 `ch_cgb/` 目录
  - 该目录按回分成 `001.md` ~ `120.md`，本项目用 `scripts/fetch_text.py` 抓取并清洗成纯文本
  - 已用 `scripts/scan_pua.py` 扫描：**120 回均无私有区坏字符**
- **纪律：整个项目只用这一个来源**
  - 不同版本（程高本 / 脂评本）的回目名和用字都有差异，混用会导致人物名对不上
  - 本项目最初手工复制过 5 回（来自另一个网页版本），后来发现与程高本差异较大
    （去空白后相似度仅 78.9%），已**全部弃用并改用统一来源**，
    旧文件保留在 `data/raw_backup_manual/` 作对照

## 七、成本（全 120 回实测）

| 项目 | 数值 |
|---|---|
| 输入 token | 676,039 |
| 输出 token | 3,170,013 |
| 合计 | **3,846,052** |
| 实测费用 | **约 ¥26.7** |

（按 DeepSeek 标准价估算：输入 ¥2/百万 token、输出 ¥8/百万 token。
实际以平台账单为准。）

**几个观察**：

1. **输出 token 是输入的 4.7 倍**。因为每条关系都要附一句"原文依据"，
   抽出来的内容比原文还长。
2. **单回波动很大**：最短的一回只输出 1.2 万 token，最长的一回输出 6.5 万
   （就是第 85 回"复读失控"那次，详见"已知局限"）。
3. 预算 1000 元，实际用了不到 3%。**算下来整本书跑一遍不到一杯奶茶钱**——
   所以"多试错几次"的成本压力几乎不存在。

## 八、已知局限（重要）

1. **别名合并不完整**。ALIAS 字典是手工维护的（已扩到 200+ 条，
   覆盖了主要人物），但 497 个人物里仍有长尾未合并的情况。

2. **关系标签过于自由**。模型生成了 **1007 种**不同的关系标签
   （"吩咐""命取杯""称谓：姐姐"……）。`classify.py` 用关键词规则能归掉约 60%，
   **仍有约 812 条（40%）归不进五大类**，这些边不画进图。

3. **部分回目抽取偏少**。对照发现：第 28 回抽出 59 条关系，第 44 回只有 7 条
   （两回人物数量接近）。**可能是模型那几次"偷懒"了**，未逐回重跑修正。

4. **隐含关系缺失**。提示词要求"只抽原文明确写到的关系"，
   未直接写明的祖孙关系（如贾母—贾宝玉）依赖模型从上下文推断，不稳定。
   这是**精度与召回的取舍**：严格规则能防止编造，但会漏掉隐含关系。

5. **无法表达关系方向**。如"黛玉对宝钗有些不忿，宝钗却浑然不觉"，
   这种单向关系当前数据结构（无向图）无法体现。

6. **关系判断未经人工全面核验**。已核验的是"引用是否忠实原文"（**99.3%**），
   **不代表关系判断本身全部正确**。

7. **第 85 回是用切分法补的**。整回发给模型会让它陷入"复读"，
   输出到 65536 token 上限被截断、返回空内容。现用 `fix_085.py`
   切成两段分别抽取再合并，**该回结果的质量与其它回不完全一致**。

## 九、如何验证结果是否可靠

**可复现的含义**：大模型的输出带有随机性，同一条提示词跑两次结果不会逐字相同。
本项目保证的是**流程可复现**——相同的输入、提示词和参数，能得到结构一致、
质量相当的结果。

**结果的质量由脚本检验，而不是靠肉眼**：

```bash
python scripts/verify_all.py
```

它做的是：把模型给出的每一条"原文依据"拿回原文里逐句比对，
统计有多少条真正忠实于原文。**这是与模型随机性无关的检验。**

**当前结果（全 120 回）**：2597 条引用中 2579 条可在原文中找到，
**忠实度 99.3%**。18 条未找到，多为"裁剪拼接"型错误或跨句拼合。

另外三个质检脚本：

```bash
python scripts/check_outputs.py   # JSON 结构与字段完整性
python scripts/scan_pua.py        # 源文本里的私有区坏字符
python scripts/check_names.py     # 核心人物名字是否完好
```

## 十、遇到问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `python 不是内部或外部命令` | 虚拟环境没激活 | 先执行 `.\.venv\Scripts\Activate.ps1` |
| `ModuleNotFoundError` | 依赖没装 | `python -m pip install -r requirements.txt` |
| `401 Authentication Fails` | Key 没读到或写错 | 检查 `.env` 的变量名和空格 |
| `402 Insufficient Balance` | 账户余额不足 | 去平台充值 |
| 提示"禁止运行脚本" | PowerShell 执行策略 | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| 图里中文显示成方框 | 系统缺中文字体 | 修改 `draw_graph.py` 里的 `font.sans-serif` 为你系统里有的一种中文字体 |

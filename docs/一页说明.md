# 红楼梦人物关系分析工具 —— 一页说明

## 一、用了哪个模型，为什么

用 DeepSeek 的 deepseek-flash（实际对应 DeepSeek-V4.1-Flash）。三个理由：

1. 中文原生，读古典白话文不需要额外处理。
2. 价格低：输入 0.3 美元/百万 token、输出 1.2 美元/百万 token，低谷时段减半。
3. 接口兼容 OpenAI 格式，用官方 openai 库就能调用，换厂商只需改两行
   （base_url 和模型名）。

一个实测发现：这个模型默认开启"思考模式"，输出前会先生成一段内部推理。
前 5 回的用量里，输出是输入的 4 倍（输入 28,116，输出 111,511），
绝大部分 token 花在"想"而不是"写"上。跑全书 120 回时，这是最主要的成本来源，
届时考虑关闭思考模式或降低推理强度。


## 二、一共花了多少钱

【总共花了9元，56,222,586Tokens】

参考数据（来自本项目的 output/run_log.txt）：

- 前 5 回抽取：输入 28,116 + 输出 111,511 = 合计 139,627 tokens
- 按上述单价估算，前 5 回费用在 1 元左右
- 另加首次调用测试、重跑等零星消耗

预算 1000 元，实际远未用尽。全书 120 回按同样方式外推，预计约 12～25 元。


## 三、中间哪里卡住了，怎么解决

1. cmd 里敲 python --version 完全没有输出（不报错、不返回）
   原因：WindowsApps 目录里有个 0 字节的占位文件排在 PATH 前面，
        把真正的解释器挡住了。
   解决：设置 → 应用 → 高级应用设置 → 应用执行别名，关掉 python.exe。
   排查手法：用 where python 命令列出系统找到的所有同名程序及其优先级。

2. VS Code 打开新文件夹后打不开终端
   原因：工作区信任（Workspace Trust）的"受限模式"会禁用终端、
        调试和部分扩展。
   解决：点顶部横幅上的 Trust this folder。

3. 激活虚拟环境时被拒绝（PSSecurityException：禁止运行脚本）
   原因：PowerShell 执行策略默认是 Restricted，不允许运行任何脚本文件。
   解决：Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

4. 取文本时维基文库打不开（ERR_TIMED_OUT）
   原因：该站在本地网络环境下连接不稳定，不是网址错、也不是操作错。
   解决：换用 purepen.com（纯文学网站）。换源前先查了它的 robots.txt，
        确认为"Disallow:"（空），即允许抓取。换源后还发现它的正文
        已是简体中文，省掉了原计划的繁转简步骤。

5. 文本中发现 14 处字符缺失（显示为方框）
   原因：老式中文网站把无法编码的生僻字塞进了 Unicode 私有区
        （U+E000–U+F8FF），属于源头缺陷，不是复制失误。
   解决：写脚本扫描全部 5 个文件，定位全部 14 处，
        确认全部落在描写性文字（服饰、器物、诗句）中，不涉及人名，
        最后决定不修正，保留数据的可追溯性。

6. 安装依赖时包被装进了全局 Python 而不是项目虚拟环境
   原因：执行 pip install 时虚拟环境未激活；屏幕上看不出任何异常，
        但包实际装到了别处。
   解决：先激活虚拟环境（确认命令行提示符前有 (.venv)）再安装。
        排查手法：python -c "import sys; print(sys.executable)"
        看输出的路径里有没有 .venv。
   附加：这一条是在"换目录验证"环节抓出来的——代码没有 bug，
        是 README 缺少警告。已在 README 第 3 步补上提示和自检命令。


## 四、如果重做一遍，会改什么

1. 重新平衡提示词的"精度与召回"
   现在的第 1 条要求是"只抽原文中明确写到的关系"。好处是不编造，
   代价是漏掉隐含关系——贾母与贾宝玉这对全书最重要的祖孙，
   前五回从未直接写明，所以图上没有这条边。
   改法：分两轮抽取。第一轮抽显性关系，第二轮专门抽隐含关系，
   结果分开标注，由使用者决定是否采信。

2. "逐字连续摘抄"这条约束还不够严
   实测 123 条引用里有 1 条属于"裁剪拼接"：模型把一段长原文拆开、
   两头粘起来当引文，用词全是原文的，但连不成一句。
   改法：明确写"允许重复引用同一句原文，不要为了区分而裁剪"
   （这一版提示词已写好，编号 v3，未使用）。

3. 关系类型应该一开始就定死枚举值
   模型自由发挥生成了 40 多种标签（"岳婿""内兄""妹丈"
   "长官与门子"……），后来靠映射表才收敛到 5 类。
   期间还发现"林如海—贾政"同时出现"内兄"和"妹丈"两种标签，
   其实是同一层关系从两个人各自角度说的。
   改法：在提示词里直接给出可选的类别清单，不让模型自由命名。

4. 数据结构要加"方向"和"阶段"两个字段
   现在无法表达"黛玉对宝钗不忿、宝钗却浑然不觉"这种单向关系，
   也无法表达"贾雨村与门子过去是贫贱之交、现在是上下级"这种
   阶段变化。

5. 别名合并应做成"半自动"
   目前是纯手工维护别名词典，边跑边漏——"可卿"就漏过一次，
   导致人物表里一度出现两个秦可卿。
   改法：让脚本先按人物共现情况给出候选对，人工只做确认。
